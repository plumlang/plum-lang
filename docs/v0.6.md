# Plum v0.6 - Variables & Type Safety

## Release Date: September 2026

## Overview

Version 0.6 introduces **variables** and **type safety** to Plum. This version adds support for both mutable and immutable variables with explicit type declarations, making Plum a statically typed language.

Plum also introduces controlled **implicit type conversion**, allowing certain safe conversions automatically while rejecting conversions that could cause data loss or unexpected behaviour.

## Core Concepts

### 1. Mutability in Plum

Plum has two types of variables based on whether they can be changed after creation:

| Keyword | Mutability | Description | Analogy |
|---------|------------|-------------|---------|
| `plant` | **Mutable** | Can be reassigned after initialization | Like a whiteboard - you can erase and write new values |
| `root` | **Immutable** | Cannot be reassigned after initialization | Like a carved stone - once set, it cannot be changed |

### 2. Mutable Variables (`plant`)

Variables declared with `plant` are **mutable**. They can be reassigned new values after initialization.

```plum
drop "=== Mutable Variables (plant) ==="

# Declare and initialize
plant int age = 21
drop age          # 21

# Reassign - this is allowed
age = 25
drop age          # 25

# Reassign using expressions
age = age + 5
drop age          # 30

# Reassign with different values
age = 100
drop age          # 100
```

### 3. Immutable Variables (`root`)

Variables declared with `root` are **immutable**. Once initialized, their values cannot be changed.

```plum
drop "=== Immutable Variables (root) ==="

# Declare and initialize
root int age = 21
drop age          # 21

# Reassignment - this is not allowed
age = 25          # Error: Cannot reassign immutable variable
```

### 4. Type Safety

Plum uses explicit type declarations to ensure that variables hold values compatible with their declared types.

Supported primitive types:

| Type | Description | Example |
|------|-------------|---------|
| `int` | Integer numbers | `plant int age = 20` |
| `float` | Decimal numbers | `plant float price = 12.5` |
| `bool` | Boolean values | `plant bool isActive = true` |
| `string` | Text values | `plant string name = "Plum"` |

A variable must receive a value compatible with its declared type. Plum performs controlled implicit conversions where they are safe.

### 5. Implicit Type Conversion

Plum supports **implicit type conversion** for selected type combinations.

The goal is to make expressions convenient without compromising type safety or silently losing information.

#### Conversion Rules

| Source Type | Target Type | Behaviour | Description |
|-------------|-------------|-----------|-------------|
| `int` | `float` | **Allowed** | Automatically converts the integer into a floating-point value |
| `float` | `int` | **Rejected** | Potential precision loss |
| `bool` | `int` | **Rejected** | Boolean values cannot be implicitly converted into integers |
| `int` | `bool` | **Rejected** | Integers cannot be implicitly converted into booleans |
| `string` | `int` | **Rejected** | Strings cannot be implicitly converted into integers |

#### 5.1 Allowed Conversion

**Integer to Float (`int → float`)**

Converting an integer to a float is safe because the target type can represent fractional values.

Plum automatically performs this conversion when required.

```plum
# Integer assigned to float
plant float price = 12
drop price          # 12.0

# Integer expression assigned to float
plant int age = 20
plant float total = age + 5

drop total          # 25.0
```

#### 5.2 Rejected Conversions

The following conversions are rejected to maintain predictable and type-safe behaviour.

**Float to Integer (`float → int`)**

```plum
plant int count = 12.5

# Type Error: Cannot implicitly convert float to int
```

Converting a float to an integer could discard the fractional part and result in precision loss.

**Boolean to Integer (`bool → int`)**

```plum
plant int value = true

# Type Error: Cannot implicitly convert bool to int
```

**Integer to Boolean (`int → bool`)**

```plum
plant bool isActive = 1

# Type Error: Cannot implicitly convert int to bool
```

**String to Integer (`string → int`)**

```plum
plant int age = "20"

# Type Error: Cannot implicitly convert string to int
```

#### 5.3 Type Conversion Summary

Plum follows these principles:

- Safe widening conversions are allowed automatically.
- Potentially lossy conversions are rejected.
- Boolean and numeric types are not implicitly interchangeable.
- String values are not automatically converted into numeric types.
- Type compatibility is checked during variable initialization and reassignment.

### 6. Type Safety During Reassignment

Type checking also applies when modifying mutable variables.

A `plant` variable can be reassigned, but the new value must remain compatible with its declared type.

```plum
plant int age = 20

# Valid reassignment
age = 25

# Invalid reassignment
age = 12.5

# Type Error: Cannot implicitly convert float to int
```

Similarly, an integer can be assigned to a mutable float variable because the conversion is allowed.

```plum
plant float price = 12

price = 15

drop price          # 15.0
```

## Summary

Plum v0.6 introduces a foundation for variable management and static type safety.

Key features:

- **Mutable variables:** `plant` allows reassignment.
- **Immutable variables:** `root` prevents reassignment.
- **Explicit type declarations:** Variables are declared with types such as `int`, `float`, `bool`, and `string`.
- **Implicit type conversion:** Safe `int → float` conversion is performed automatically.
- **Strict type checking:** Unsafe or unsupported conversions are rejected.
- **Reassignment validation:** Mutable variables must preserve type compatibility.

These rules help Plum maintain predictable behaviour while allowing convenient operations where type conversion is safe.
