# Plum v0.10 — Bitwise Operators & Compound Assignment

## 1. Overview

Plum v0.10 introduces bitwise operators and compound assignment operators, extending the language's support for integer-level operations and variable updates.

This release updates the lexer, parser, and interpreter while preserving existing logical operators and language behavior.

## 2. New Features

### Bitwise Operators

| Operator | Name | Description | Example | Result |
|---|---|---|---|---:|
| `&` | Bitwise AND | Sets bits present in both operands | `5 & 3` | `1` |
| `\|` | Bitwise OR | Sets bits present in either operand | `5 \| 3` | `7` |
| `^` | Bitwise XOR | Sets bits that differ between operands | `5 ^ 3` | `6` |
| `~` | Bitwise NOT | Inverts the bits of an operand | `~5` | `-6` |

Bitwise operators require integer-valued numeric operands. Fractional values such as `5.5` are rejected.

### Compound Assignment Operators

Compound assignment operators update a variable by applying an operation to its current value.

| Operator | Equivalent operation | Example |
|---|---|---|
| `+=` | `a = a + value` | `a += 5` |
| `-=` | `a = a - value` | `a -= 2` |
| `*=` | `a = a * value` | `a *= 3` |
| `/=` | `a = a / value` | `a /= 2` |
| `%=` | `a = a % value` | `a %= 4` |

These operators support expressions on the right-hand side and use Plum's existing variable type-coercion rules. Assignments to undefined variables and constants are rejected, and unsupported operations produce runtime errors.

### Logical Operator Compatibility

Existing logical operators remain supported:

- `&&` — Logical AND
- `||` — Logical OR
- `!` — Logical NOT

Single-character `&` and `|` are distinguished from their double-character logical counterparts.

## 3. Usage Examples

### Bitwise Operations

```plum
drop(5 & 3)
drop(5 | 3)
drop(5 ^ 3)
drop(~5)

drop(12 & 10)
drop(12 | 10)
drop(12 ^ 10)
```

Expected output:

```text
1
7
6
-6
8
14
6
```

### Negative Numbers and Edge Cases

```plum
drop(0 & 0)
drop(7 ^ 7)
drop(~0)
drop(~(-1))
```

Expected output:

```text
0
0
-1
0
```

### Compound Assignment

```plum
plant int a = 10

a += 5
drop(a)

a -= 2
drop(a)

a *= 3
drop(a)

a /= 3
drop(a)

a %= 4
drop(a)
```

Expected output:

```text
15
13
39
13
1
```

### Expressions and Operator Precedence

Arithmetic expressions are evaluated before bitwise operations. Bitwise AND has higher precedence than XOR, which has higher precedence than OR. In the current parser, bitwise operations also bind more tightly than comparisons.

```plum
drop(2 + 3 & 1)
drop(6 | 3 ^ 1 & 3)
drop((5 | 2) & 3)
drop(5 & 3 == 1)
```

Expected output:

```text
1
6
3
true
```

Parentheses can be used to make evaluation order explicit.

Compound assignment also supports expressions:

```plum
plant int a = 10
plant int b = 5

a += b * 2
drop(a)

a -= b - 2
drop(a)
```

Expected output:

```text
20
17
```

## 4. Implementation

The v0.10 implementation updates the following components:

- **Lexer (`plum/lexer/`)** — Recognizes bitwise operators and compound assignment tokens while preserving existing logical operators.
- **Parser (`plum/parser/`)** — Handles bitwise operator precedence and parses compound assignment statements.
- **AST (`plum/plum_ast/`)** — Uses the existing unary and binary operation nodes for bitwise operations and adds a `CompoundAssignment` node for compound assignments.
- **Interpreter (`plum/interpreter/`)** — Evaluates bitwise and compound assignment operations, applies existing type-coercion rules, and handles unsupported operand types and division or modulo by zero.

## 5. Testing

The example suites cover:

- Basic AND, OR, XOR, and NOT operations.
- Zero, identical operands, and different bit patterns.
- Negative numbers and logical operator compatibility.
- Operator precedence and parentheses.
- Compound assignment with all five supported operators.
- Compound assignment with right-hand-side expressions.
- Error handling for unsupported operand types and division or modulo by zero.
- Regression checks for the existing bitwise, shift, and v0.9 extended examples.

The tested examples produced their expected outputs during manual regression testing.

## 6. Limitations

- Bitwise operations do not accept fractional numeric operands.
- Compound assignment behavior follows the language's existing type-coercion rules.
- Shift operators (`<<` and `>>`) are implemented separately from the bitwise operators described here.
- Runtime errors may still display Python tracebacks; cleaner user-facing error reporting remains a potential improvement.

## 7. Next Steps

Potential future improvements include cleaner runtime error messages, automated regression tests, and further operator and language-feature development.
