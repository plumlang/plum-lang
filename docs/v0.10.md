# Plum v0.10 — Bitwise, Shift & Compound Assignment Operators

## 1. Overview

Plum v0.10 expands the language's operator support with bitwise operators, bitwise shift operators, and compound assignment operators.

This release extends the existing lexer, parser, and interpreter while preserving logical operators and existing language behavior.

## 2. New Features

### Bitwise Operators

| Operator | Name | Description | Example | Result |
|---|---|---|---|---:|
| `&` | Bitwise AND | Sets bits that are set in both operands | `5 & 3` | `1` |
| `\|` | Bitwise OR | Sets bits that are set in either operand | `5 \| 3` | `7` |
| `^` | Bitwise XOR | Sets bits that differ between operands | `5 ^ 3` | `6` |
| `~` | Bitwise NOT | Inverts the bits of an operand | `~5` | `-6` |

Bitwise operators require integer-valued numeric operands. Fractional values such as `5.5` are rejected.

### Shift Operators

| Operator | Name | Description | Example | Result |
|---|---|---|---|---:|
| `<<` | Left shift | Shifts bits to the left | `5 << 1` | `10` |
| `>>` | Right shift | Shifts bits to the right | `20 >> 2` | `5` |

Shift operators require integer-valued numeric operands.

### Compound Assignment Operators

Compound assignment applies an operation to an existing variable and stores the result back into that variable.

| Operator | Equivalent operation |
|---|---|
| `+=` | `a = a + value` |
| `-=` | `a = a - value` |
| `*=` | `a = a * value` |
| `/=` | `a = a / value` |
| `%=` | `a = a % value` |
| `//=` | `a = a // value` |
| `**=` | `a = a ** value` |
| `&=` | `a = a & value` |
| `\|=` | `a = a \| value` |
| `^=` | `a = a ^ value` |
| `<<=` | `a = a << value` |
| `>>=` | `a = a >> value` |

Bitwise and shift compound assignments require integer-valued operands. Compound assignments preserve the existing checks for undefined variables and constants.

### Logical Operator Compatibility

Existing logical operators remain supported:

- `&&` — Logical AND
- `||` — Logical OR
- `!` — Logical NOT

Single-character `&` and `|` are distinguished from their double-character logical counterparts.

## 3. Usage Examples

### Bitwise Operations

```plum
drop(5 & 3)    # 1
drop(5 | 3)    # 7
drop(5 ^ 3)    # 6
drop(~5)       # -6

drop(12 & 10)  # 8
drop(12 | 10)  # 14
drop(12 ^ 10)  # 6
```

### Shift Operations

```plum
drop(5 << 1)   # 10
drop(20 >> 2)  # 5
drop(3 << 2)   # 12
drop(16 >> 4)  # 1
```

### Compound Assignment

```plum
plant int a = 10

a += 5
drop(a)       # 15

a -= 2
drop(a)       # 13

a *= 3
drop(a)       # 39

a /= 3
drop(a)       # 13

a %= 4
drop(a)       # 1
```

### Extended Compound Assignment

```plum
plant int a = 16
a //= 3
drop(a)       # 5

plant int b = 2
b **= 3
drop(b)       # 8

plant int c = 6
c &= 3
drop(c)       # 2

plant int d = 6
d |= 3
drop(d)       # 7

plant int e = 6
e ^= 3
drop(e)       # 5

plant int f = 4
f <<= 2
drop(f)       # 16

plant int g = 16
g >>= 2
drop(g)       # 4
```

### Negative Numbers and Edge Cases

```plum
drop(0 & 0)    # 0
drop(7 ^ 7)    # 0
drop(~0)       # -1
drop(~(-1))    # 0
drop(-8 >> 1)  # -4
```

### Operator Precedence

Arithmetic expressions are evaluated before bitwise operations. Bitwise AND has higher precedence than XOR, which has higher precedence than OR. In the current parser, bitwise operations also bind more tightly than comparisons.

```plum
drop(2 + 3 & 1)       # 1
drop(6 | 3 ^ 1 & 3)   # 6
drop((5 | 2) & 3)     # 3
drop(5 & 3 == 1)      # true
```

Parentheses can be used to make evaluation order explicit.

## 4. Implementation

The v0.10 implementation extends three main components:

- **Lexer (`plum/lexer/`)** — Recognizes bitwise operators, shift operators, and compound assignment tokens while preserving existing logical and comparison operators.
- **Parser (`plum/parser/`)** — Recognizes compound assignment statements and maintains the existing expression parsing and operator precedence rules.
- **Interpreter (`plum/interpreter/`)** — Evaluates the new compound assignments, validates integer-valued operands for bitwise and shift assignments, and preserves variable and constant checks.

The implementation reuses the existing `CompoundAssignment` AST node; no separate AST node types are required for each operator.

## 5. Testing

The v0.10 examples and regression checks cover:

- Bitwise AND, OR, XOR, and NOT.
- Shift operators `<<` and `>>`.
- All seven extended compound assignment operators: `//=`, `**=`, `&=`, `|=`, `^=`, `<<=`, and `>>=`.
- Existing arithmetic compound assignments: `+=`, `-=`, `*=`, `/=`, and `%=`.
- Negative numbers, zero values, and operator precedence.
- Compatibility with logical operators and comparison operators.
- Fractional operand rejection for bitwise compound assignments.
- Division-by-zero handling for floor division assignment.
- Regression checks for existing bitwise, shift, compound assignment, and v0.9 loop examples.

Runtime errors currently display Python tracebacks; cleaner user-facing error reporting remains a potential improvement.

## 6. Limitations

- Bitwise and shift operations require integer-valued numeric operands.
- Compound assignments cannot reassign constants or target undefined variables.
- Runtime errors may display Python tracebacks instead of concise language-level error messages.

## 7. Next Steps

Potential future improvements include:

- Cleaner user-facing runtime error messages.
- More automated lexer, parser, and interpreter tests.
- Expanded language features and improved diagnostics.
