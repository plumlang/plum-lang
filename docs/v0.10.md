
# Plum v0.10 — Bitwise Operators

## 1. Overview

Plum v0.10 introduces bitwise operators, allowing programs to perform operations on the binary representations of integer values.

This release extends the existing lexer, parser, and interpreter while preserving logical operators and existing language behavior.

## 2. New Features

### Bitwise Operators

| Operator | Name | Description | Example | Result |
|---|---|---|---|---:|
| `&` | Bitwise AND | Sets bits that are set in both operands | `5 & 3` | `1` |
| `|` | Bitwise OR | Sets bits that are set in either operand | `5 | 3` | `7` |
| `^` | Bitwise XOR | Sets bits that differ between operands | `5 ^ 3` | `6` |
| `~` | Bitwise NOT | Inverts the bits of an operand | `~5` | `-6` |

Bitwise operators require integer-valued numeric operands. Fractional values such as `5.5` are rejected.

### Logical Operator Compatibility

Existing logical operators remain supported:

- `&&` — Logical AND
- `||` — Logical OR
- `!` — Logical NOT

Single-character `&` and `|` are distinguished from their double-character logical counterparts.

## 3. Usage Examples

```plum
drop(5 & 3)    # 1
drop(5 | 3)    # 7
drop(5 ^ 3)    # 6
drop(~5)       # -6

drop(12 & 10)  # 8
drop(12 | 10)  # 14
drop(12 ^ 10)  # 6
```

### Negative Numbers and Edge Cases

```plum
drop(0 & 0)    # 0
drop(7 ^ 7)    # 0
drop(~0)       # -1
drop(~(-1))    # 0
```

### Operator Precedence

Arithmetic expressions are evaluated before bitwise operations. Bitwise AND has higher precedence than XOR, which has higher precedence than OR. In the current parser, bitwise operations also bind more tightly than comparisons.

```plum
drop(2 + 3 & 1)       # 1
drop(6 | 3 ^ 1 & 3)   # 6
drop((5 | 2) & 3)     # 3
drop(5 & 3 == 1)      # true
```

Parentheses can be used to make evaluation order explicit.

## 4. Implementation

The v0.10 implementation updates three main components:

- **Lexer (`plum/lexer/`)** — Recognizes `&`, `|`, `^`, and `~`, while preserving `&&`, `||`, and `!`.
- **Parser (`plum/parser/`)** — Adds bitwise operator precedence and constructs the existing unary and binary operation AST nodes.
- **Interpreter (`plum/interpreter/`)** — Evaluates bitwise operations and rejects fractional or otherwise unsupported operands.

No separate AST node types were required for these operators.

## 5. Testing

The bitwise example suite covers:

- Basic AND, OR, XOR, and NOT operations.
- Zero, identical operands, and different bit patterns.
- Negative numbers.
- Logical operator compatibility.
- Operator precedence and parentheses.

Invalid fractional operands were checked for all four bitwise operators. Existing logical edge tests and the v0.9 extended loop example also passed during regression testing.

## 6. Limitations

- Bitwise operations do not accept fractional numeric operands.
- Shift operators (`<<` and `>>`) are not included in this release.
- Runtime errors currently display Python tracebacks; cleaner user-facing error reporting remains a potential improvement.

## 7. Next Steps

Potential future improvements include shift operators, improved runtime error reporting, and additional automated tests.
